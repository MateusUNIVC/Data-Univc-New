# Academic Excel Official — Controlled Production Cutover (02D)

> **Atualização 2026-10-02:** o Excel Oficial acadêmico agora é o padrão. `ACADEMIC_EXCEL_OFFICIAL_ENABLED=false` deve ser usado somente como rollback explícito. Este runbook permanece como referência histórica de cutover.


## Purpose

This runbook activates the Excel Official engine for the existing authenticated `GET /api/excel-interativo` route only after fresh DTNH and DCS production parity evidence is accepted.

The route, permissions, query parameters and frontend download URL do not change. Only the internal workbook engine changes.

The production default remains:

```env
ACADEMIC_EXCEL_OFFICIAL_ENABLED=false
```

Rollback is intentionally simpler than activation: disabling the flag never requires parity evidence.

## Safety model

Activation requires all of the following at the same time:

1. a DTNH parity JSON generated from an authorized **production** snapshot;
2. a DCS parity JSON generated from an authorized **production** snapshot;
3. both reports individually `READY`;
4. zero semantic failures;
5. source-quality gate passed;
6. Academic V3 and Excel Official workbook build evidence passed;
7. Excel Official release audit passed;
8. both reports generated by the same `APP_VERSION` and `SCHEMA_VERSION` as the code being activated;
9. both reports are within the configured evidence age window (24h by default);
10. the exact report bytes still match the SHA-256 hashes recorded in the cutover manifest.

A fixture/local report can never unlock production activation.

## 1. Deploy code with the flag OFF

On the VPS, update the application while keeping the current engine active:

```bash
cd /opt/data-univc
git pull
docker compose -f docker-compose.production.yml up -d --build --force-recreate app
curl -fsS http://127.0.0.1:8000/api/health/ready
```

Confirm the persisted flag:

```bash
python scripts/manage_academic_excel_cutover.py status --env-file .env.production
```

Expected:

```text
ACADEMIC_EXCEL_OFFICIAL_ENABLED=false
```

## 2. Generate DTNH and DCS production parity reports

Use the 02C parity harness with snapshots obtained through the authorized production repository/session. Production evidence must not be fabricated from demo/fixture data.

The resulting files should be equivalent to:

```text
parity_output/academic_parity_dtnh.json
parity_output/academic_parity_dcs.json
```

Each report must show `cutover_status = READY`.

## 3. Build the cutover manifest

```bash
python scripts/manage_academic_excel_cutover.py gate \
  --dtnh-report parity_output/academic_parity_dtnh.json \
  --dcs-report parity_output/academic_parity_dcs.json \
  --output-dir cutover_output \
  --max-age-hours 24
```

Success produces:

```text
cutover_output/academic_excel_cutover_manifest.json
cutover_output/academic_excel_cutover_manifest.md
```

The command exits non-zero when the gate is `BLOCKED`.

Do not continue unless the manifest status is `READY`.

## 4. Activate the flag atomically

Activation re-reads the two reports, re-checks freshness/version/quality and verifies that their current SHA-256 hashes still match the manifest.

```bash
python scripts/manage_academic_excel_cutover.py activate \
  --manifest cutover_output/academic_excel_cutover_manifest.json \
  --dtnh-report parity_output/academic_parity_dtnh.json \
  --dcs-report parity_output/academic_parity_dcs.json \
  --env-file .env.production \
  --confirm ENABLE_EXCEL_OFFICIAL
```

The command:

- creates a timestamped backup of `.env.production` when a change is necessary;
- writes `ACADEMIC_EXCEL_OFFICIAL_ENABLED=true` atomically;
- does **not** restart the application by itself.

## 5. Restart only the application container

```bash
docker compose -f docker-compose.production.yml up -d --force-recreate app
curl -fsS http://127.0.0.1:8000/api/health/ready
```

Confirm the running process loaded the new flag:

```bash
docker compose -f docker-compose.production.yml exec -T app \
  python -c "from excel_service import selected_academic_excel_engine; print(selected_academic_excel_engine())"
```

Expected:

```text
excel_official
```

## 6. Authenticated route smoke test — DTNH

The smoke script never prints the session cookie. Put the full Cookie header from an authorized DTNH session into an environment variable without placing the secret on the command line:

```bash
read -s -p "DTNH Cookie header: " DTNH_SMOKE_COOKIE
export DTNH_SMOKE_COOKIE
printf '\n'

python scripts/smoke_academic_excel_cutover.py \
  --base-url http://127.0.0.1:8000 \
  --directorate DTNH \
  --cookie-env DTNH_SMOKE_COOKIE \
  --window 4 \
  --output /tmp/dtnh_excel_official_smoke.xlsx

unset DTNH_SMOKE_COOKIE
```

The smoke test checks:

- `/api/health/ready`;
- HTTP 200 from `/api/excel-interativo`;
- XLSX MIME/ZIP structure;
- `X-Data-UNIVC-Excel-Engine: excel_official`;
- six required institutional sheets;
- workbook directorate custom metadata;
- app/schema metadata;
- absence of external links and VBA/macros.

## 7. Authenticated route smoke test — DCS

Repeat with a DCS-authorized session:

```bash
read -s -p "DCS Cookie header: " DCS_SMOKE_COOKIE
export DCS_SMOKE_COOKIE
printf '\n'

python scripts/smoke_academic_excel_cutover.py \
  --base-url http://127.0.0.1:8000 \
  --directorate DCS \
  --cookie-env DCS_SMOKE_COOKIE \
  --window 4 \
  --output /tmp/dcs_excel_official_smoke.xlsx

unset DCS_SMOKE_COOKIE
```

Both directorates must pass before the cutover is considered operationally complete.

## 8. Observe application logs

```bash
docker compose -f docker-compose.production.yml logs --tail=200 app
```

Academic exports now log `excel_engine=excel_official`. The authenticated download also returns the engine in the response header.

Review export errors, 5xx responses and generation duration/size before continuing with later migration phases.

## Immediate rollback

Rollback does not require a manifest or parity evidence:

```bash
cd /opt/data-univc
python scripts/manage_academic_excel_cutover.py rollback --env-file .env.production
docker compose -f docker-compose.production.yml up -d --force-recreate app
curl -fsS http://127.0.0.1:8000/api/health/ready
```

Confirm:

```bash
docker compose -f docker-compose.production.yml exec -T app \
  python -c "from excel_service import selected_academic_excel_engine; print(selected_academic_excel_engine())"
```

Expected after rollback:

```text
academic_v3
```

The legacy Academic V3 builder remains in the codebase during the observation period. Do not delete it as part of 02D.

## Acceptance criteria

02D production cutover is complete only when:

- DTNH production report is `READY`;
- DCS production report is `READY`;
- cutover manifest is `READY` and unexpired;
- flag activation succeeds;
- application restarts healthy;
- running engine reports `excel_official`;
- DTNH authenticated route smoke passes;
- DCS authenticated route smoke passes;
- no material export errors are observed immediately after activation.

If any item fails, rollback to `ACADEMIC_EXCEL_OFFICIAL_ENABLED=false` before investigating.
